# @azumag/opencode-rate-limit-fallback

[English](README.md) | **日本語**

レート制限からの復帰を補助する、非公式のOpenCodeプラグインです。**2.xのエントリーポイントは同じセッションを待機・再開するもので、モデル切り替えは行いません。** モデル切り替えは旧1.x系の機能です。

プロバイダーの利用上限を解除したり、追加の利用枠を取得したりするツールではありません。アカウントや認証情報は管理せず、OpenCodeの公式製品・公認プラグインでもありません。

## バージョンの選び方

| OpenCodeのプラグイン方式 | パッケージ | 対応機能 |
| --- | --- | --- |
| `plugins`を使うv2 / Web | 2.x、npmタグ`opencode-v2` | `wait`のみ。同じセッションを指数バックオフで再開 |
| `plugin`を使うv1 | 1.x。掲載する固定バージョンは`1.70.11` | モデル切り替え、`cycle`、`stop`、`retry-last`、固定間隔の`wait` |

このブランチのソースは**2.0.3**です。公開前はnpmタグが以前のリリースを指している場合があります。後述の待機時間の検証とHTTP 401/403への対策は2.0.3で追加したもので、既存の2.0.2には適用されません。

```sh
npm view @azumag/opencode-rate-limit-fallback dist-tags --json
```

v1のホストに2.xを導入しないでください。開発用のOpenCode plugin / SDKパッケージは`1.18.16`に固定していますが、**すべてのv2/Web版で実機確認済みという意味ではありません。** v2アダプターのテストはフックを模擬したものです。無人運用に使う前に、ホストが必要な`prompt`・`retry`フックに対応していることを確認してください。

## 最小構成：v2で同じモデルを待つ

**OpenCode本体の設定**にプラグインを追加します。v1用の`latest`ではなくv2用タグを指定します。リリースを確認した後は、再現性のためにバージョン番号を固定してください。

```json
{
  "plugins": ["@azumag/opencode-rate-limit-fallback@opencode-v2"]
}
```

これとは**別のプラグイン設定ファイル**を`~/.opencode/rate-limit-fallback.json`に作成します。ディレクトリがなければ先に作成してください。

```json
{
  "enabled": true,
  "fallbackMode": "wait",
  "cooldownMs": 60000,
  "fallbackModels": []
}
```

プラグインを実行しているOpenCodeプロセスを再起動します。モデルの選択と認証はOpenCode本体で行います。**このプラグインのJSONにAPIキー、Cookie、パスワード、プロバイダーの認証情報を記入しないでください。**

`fallbackMode: "wait"`の明示が必要です。共有設定の初期値は`"cycle"`であり、そのままではv2アダプターは動作しません。`wait`は切り替え先を選ばないため、`fallbackModels`は空配列で問題ありません。

## v2の動作と設定

HTTP 429や、レート・利用枠に関する一部のエラー文言を検出すると、既存セッションの再試行を要求します。別のプロバイダーやモデルは選択しません。

上の設定では、該当するエラーが繰り返されると、待機時間が**60秒、120秒、240秒、…、1時間**と増えます。新しい空でないユーザープロンプトが届くと、アダプターの再開タイマーを取り消して待機時間を初期化します。自動再開用の空プロンプトは待機回数を引き継ぎます。成功しただけでは、このアダプターの待機回数は初期化されません。

| 設定 | 動作 |
| --- | --- |
| `enabled` | 初期値`true`。`false`にしてホストを再起動すると無効化 |
| `fallbackMode` | v2では`"wait"`が必須。他のモードではフックを登録しない |
| `cooldownMs` | 初回待機時間。初期値`60000`ミリ秒、実効下限`1000`ミリ秒 |
| `fallbackModels` | v2では切り替え先の選択に使用しない。`[]`でよい |

2.0.3以降、`cooldownMs`は有限・非負のJSON数値で、上限は`2147483397`です。不正な値では、危険なタイマーを作らず、フック登録前にプラグインの初期化を失敗させます。1時間を超える有効な設定は維持し、バックオフの上限は常に1時間ではなく`max(3600000, cooldownMs)`となります。プロバイダーが長い間隔を要求する場合を除き、まずは例の60秒を使用してください。

2.0.3以降、明示的なHTTP **401/403**は、文面にquotaが含まれていても、このアダプターの再試行を停止し、そのセッションに予約済みの再開タイマーも取り消します。そのステータス情報が渡されないエラーは文言判定に依存するため、誤検出の可能性が残ります。

### 重要な制約

- `wait`には、意図的に**総再試行回数・総待機時間の上限がありません**。アダプターが想定するクライアント側の試行上限である5回目以降は、待機時間に250ミリ秒を加えて、同じセッションを空プロンプトで再開します。サーバー側の利用上限を解除する動作でも、必ず復旧する保証でもありません。
- **`Retry-After`や利用枠のリセット時刻は解析しません。** 待機時間のランダム化もありません。プロバイダー指定の再試行間隔を守れない運用には使用せず、大量のセッションを同時待機させないでください。
- v1の`retryPolicy`、サーキットブレーカー、独自エラーパターン、メトリクス、動的モデル優先順位、設定の自動再読込、`headlessOnRateLimit`は、**v2のエントリーポイントでは未実装**です。設定に書いてもv2の安全上限にはなりません。
- v2には停止・セッション削除専用のライフサイクルフックがありません。画面の停止ボタン、セッション削除、ブラウザーのタブを閉じる操作だけで、サーバー側の予約タイマーが消えるとは限りません。確実にこのプラグインの予約処理を止めるには、**OpenCodeのホストプロセスを終了し、`enabled: false`にして再起動**してください。新しいプロンプトは前のタイマーを取り消しますが、新たな処理も開始します。

遅延後の再開によって、エージェントに許可されたツール操作が続行される可能性があります。時間が経ってから再開することを踏まえ、ホストのツール権限と承認設定を調整してください。

## 設定ファイルの探索順

最初に読み込み・受理できた設定を使用し、複数ファイルは重ね合わせません。v2の探索順は次のとおりです。

1. `<directory>/.opencode/rate-limit-fallback.json`、次に`<directory>/rate-limit-fallback.json`。
2. `$HOME/.opencode/rate-limit-fallback.json`、次に`$HOME/rate-limit-fallback.json`。
3. `$XDG_CONFIG_HOME/opencode/rate-limit-fallback.json`、次に`$XDG_CONFIG_HOME/rate-limit-fallback.json`。未設定時の`XDG_CONFIG_HOME`は`$HOME/.config`です。

v2はプロジェクトとworktreeに同じディレクトリを渡します。v1は別のworktreeをプロジェクトより先に探索できます。プロジェクト内の設定がグローバル設定を上書きするため、信頼できないリポジトリを開く前に内容を確認してください。v2で設定を変更した場合はホストの再起動が必要です。

## OpenCode Goの規約・料金・プライバシー

**2026年9月14日**に[Goの公式文書](https://opencode.ai/docs/go/)と[利用規約](https://opencode.ai/legal/terms-of-service)を確認しています。規約は変更される場合があります。

Goは通常のコーディングエージェント利用を説明する一方、ホスト型サービスの規約には、アカウントを使った上限回避、過大な負荷、一部の自動処理に関する制限があります。**READMEの記載やバックオフの実装だけで、無制限の無人運用が許可されるわけではありません。** 判断が曖昧な運用は提供元に確認してください。本プロジェクトは規約適合を保証しません。MITライセンスはプラグインのコードに対するもので、ホスト型モデルの利用許諾ではありません。

正当に利用できるアカウントと、対応するホストのリクエスト経路を使用してください。上限回避のためのアカウント切り替えやクライアント・セッション識別情報の偽装は行わないでください。本プラグインは独自のプロバイダー向け通信を組み立てず、OpenCodeに処理を委ねます。クライアント・セッションヘッダーの送信はホスト側の責任範囲です。

Goの**Use balance**を有効にすると、定額枠到達後にZen残高を消費する場合があります。自動再開の前に課金設定を確認してください。また、学習利用と保存期間はモデルごとに異なり、Goの全モデルが同じプライバシー条件とは限りません。v1のフォールバックでは、会話内容や添付が**別のプロバイダー**へ再送され、料金やデータ取扱条件が変わる可能性があります。

## データの取り扱いと安全な報告

v2アダプター自身は、プロバイダーの認証情報を読み込まず、会話ログを出力せず、独立したテレメトリー送信先も呼び出しません。ローカルのプラグイン設定を読み、セッションID・待機回数・タイマーをメモリー内に保持します。ただし再開後の処理はOpenCodeと設定先プロバイダーを通るため、**オフライン処理でも、ホスト側がログを保存しないという保証でもありません。**

旧v1の機能では、モデル健全性の統計をローカル保存し、任意設定のメトリクスを出力し、学習したエラーパターンを設定に書き戻し、OpenCodeのアプリケーションログへ診断情報を送る場合があります。パス、セッションID、設定値、プロバイダーのエラーを含む可能性があり、完全な秘密情報のマスキング機能ではありません。

Issueに共有する前に、ログ、設定、スクリーンショット、テスト結果、コミット情報を確認・伏せ字化してください。`.env`、`auth.json`、トークン入りの`.npmrc`、秘密鍵、実際の会話はアップロードしないでください。`.gitignore`は今後の混入防止には役立ちますが、Git履歴、過去のPR、公開済みパッケージ、キャッシュにある情報を削除するものではありません。自動検査で秘密情報が検出されなかったことと、個人情報が一切存在しないことは別です。

## OpenCode v1を使う場合

v1系のパッケージを維持してください。

```json
{
  "plugin": ["@azumag/opencode-rate-limit-fallback@1.70.11"]
}
```

上の最小構成の`wait`設定はv1でも使用できますが、待機時間は指数的には増加せず固定です。モデル切り替えやヘッドレス実行を設定する前に、[v1設定リファレンス（英語）](docs/v1-reference.md)と[v1の待機モード（英語）](docs/quota-wait-mode.md)を確認してください。
